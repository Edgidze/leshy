# План: подборки грибов по странам

Статус: **Phase 0 готов** (Phase 1 следующий). Отмечать фазы `[x]` по мере
выполнения. Каждая фаза — отдельная сессия. Не переносить сюда код/детали
реализации после того, как фаза сделана — итоговые неочевидные решения идут
в `presentation/CLAUDE.md` / `data/CLAUDE.md`, этот файл только про план
вперёд. Когда все фазы, включая Phase 5, закрыты — файл можно удалить.

## Идея

Сейчас каталог из 30 видов — единая («базовая») подборка. Нужно разбить его
на подборки по странам, дать пользователю выбирать, какие подборки/виды ему
интересны, и не потерять при этом уже собранные данные при переключении
подборок. Демо-подборки (произвольно нарезанные из текущих 30) — на первых
фазах, финальные подборки по странам — отдельно, позже (Phase 5).

## Модель данных (два независимых флага + одна денормализация)

| Поле | Смысл | Пишет | Читает |
|---|---|---|---|
| `Category.isActive` (уже есть, не менять) | «показывать на Карте и в ленте Записи» | экран Фильтра (как сейчас) | Map, Record — без изменений |
| `Category.isPicked` (новое) | «пользователь выбрал этот гриб через подборки» | пикер подборок (Настройки + первый запуск) | используется при пересчёте `isFilterEligible` |
| `Category.isFilterEligible` (новое, денормализация) | «показывать в списке экрана Фильтра» | пересчитывается целиком при каждом сохранении пикера подборок (+ разово при старте приложения) | экран Фильтра — простой `WHERE`, без JOIN/EXISTS |

Правило пересчёта `isFilterEligible` (по всем категориям разом, при
сохранении пикера или старте приложения):

```
isFilterEligible = isPicked || existsFieldMark(categoryId)
```

Сортировка на экране Фильтра: `isPicked DESC`, затем обычный порядок
категорий — «унаследованные» виды (уже есть находки, но подборка снята)
уходят вниз списка, но не пропадают, пока не собраны существующим правилом.

**Известный краевой случай (сознательно не решается сейчас):** если у
непикнутого «унаследованного» вида удалить последнюю находку (кнопка «−»),
`isFilterEligible` не сбросится немедленно — вид останется в нижней группе
Фильтра до следующего сохранения пикера. Безвредно (пустой тумблер), само
исправляется при следующем сохранении подборок — не стоит городить пересчёт
на каждое удаление находки ради этого.

`collections`/`category_collections` — новые таблицы, `category_collections`
— много-ко-многим (один гриб может входить в несколько подборок стран).
Подборки не хранят собственный флаг «выбрана» — это производное состояние
(все/часть/ни один участник `isPicked=true`), чекбокс всей подборки в UI —
просто bulk-запись `isPicked` по всем её участникам.

## Mac vs Windows

Вся фича — `shared/commonMain` (Room + DataStore + Compose), без
`expect`/`actual`, без нативных SDK. Ждать Mac не нужно — компиляция iOS
проверяется как обычно (`:shared:compileKotlinIosArm64` /
`compileKotlinIosSimulatorArm64`) на Windows по ходу дела. Один Mac-сеанс
приберечь на Phase 4 — визуальная проверка на симуляторе разом для всех
новых/изменённых экранов, вместо переключения машины на каждой фазе.

## Фазы

- [x] **Phase 0 — Схема.** Room v4→v5: таблицы `collections`,
  `category_collections` (many-to-many, `ON DELETE CASCADE` в обе стороны),
  новые колонки `categories.isPicked`/`isFilterEligible` (`DEFAULT 1`).
  `EnsureDefaultCollectionsUseCase` сидирует 3 демо-подборки (north/south/
  east), нарезанные из нынешних 30 видов, с намеренным пересечением двух пар
  видов между соседними подборками (проверка many-to-many). Тот же
  upsert-diff паттерн, что `EnsureDefaultCategoriesUseCase`; вызывается сразу

  новый). Домен: `Collection`, `CollectionRepository`/`Impl`, `Category`
  получил `isPicked`/`isFilterEligible` (default `true`, дописаны в конец
