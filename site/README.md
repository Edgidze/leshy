# `site/` — публичные страницы приложения

Здесь лежит то, что должно быть доступно по URL, а не внутри приложения. Две страницы —
политика конфиденциальности и поддержка — плюс текстовый файл с отпечатками данных.

`privacy.html` — самодостаточный файл: ни CSS, ни шрифтов, ни скриптов снаружи не тянет,
работает из любого места, куда его положат. Четыре языковые версии (ru, en, fr, es) лежат в одном
файле, переключатель — справа сверху; по умолчанию берётся язык браузера, а `#ru`/`#en`/`#fr`/`#es`
в адресе перебивает его (приложение может привести на нужную версию явно). Скрипт внизу — только
удобство: с выключенным JS страница показывает все четыре версии подряд, и ни один текст, адрес или
ссылка не пропадают.

Адрес для связи — `fefradkin@gmail.com` — вписан прямо в разметку, по три ссылки (разделы 1, 8, 10)
на каждый язык, всего двенадцать. Менять — во всех сразу, поиском по файлу.

**Страница обязана быть полноценной без JavaScript** — так её видит проверяющий из магазина, и так
её читает всё, что не исполняет скрипты. Скрипт внизу файла только прячет лишние языковые версии и
показывает переключатель; без него страница выводит все четыре версии подряд, и ни один текст,
адрес или ссылка не теряются. Отсюда правило: **ничего содержательного из скрипта не подставлять**
— ни адрес почты, ни даты, ни названия. Именно поэтому адрес двенадцать раз вписан руками, а не
одной переменной.

**Файл в репозитории обязан совпадать с опубликованным.** Если страницу правили на стороне
хостинга, сначала скачайте её обратно сюда, потом правьте: расхождение между тем, что читает
пользователь, и тем, что лежит в проекте, — это ровно тот случай, когда проверка «соответствует ли
политика коду» проверяет не тот файл.

## `support.html` — страница поддержки

Появилась ради App Store Connect: **Support URL — обязательное поле листинга**, и ссылкой на
почту его не закрыть (у Google Play аналога нет вовсе, там хватает адреса разработчика). Устроена
ровно как `privacy.html` — те же стили, те же четыре языка в одном файле, тот же переключатель,
та же обязанность работать без JavaScript, тот же адрес `fefradkin@gmail.com`, вписанный руками
(здесь — по два раза на язык, всего восемь).

Содержание — то, что реально снимает письма: что прислать в отчёте об ошибке (модель устройства,
версия системы, версия приложения, что делали), и пять частых вопросов (съедобность не
определяется, карта без сети, геопозиция, перенос прогулок, язык интерфейса).

**Названия пунктов меню в тексте — ровно те, что видит пользователь** (`StringKey.NavData` →
«Экспорт/Импорт», `StringKey.NavPreparation` → «Предзагрузка», `StringKey.AboutTitle` →
«О приложении»), на каждом из четырёх языков своё. Переименуется пункт — правится и здесь.

## Публикация на GitHub Pages

Страницы живут **не в этом репозитории**, а в отдельном — `leshy-mapper/mushrooms-map`, чтобы
Pages не раздавал заодно внутренние заметки из `docs/`. Источник истины остаётся здесь, в
`site/`.

**Способ публикации — ручная загрузка через веб-интерфейс GitHub** (предпочтение владельца;
`git subtree push` для этого репозитория не используется):

1. Открыть `https://github.com/leshy-mapper/mushrooms-map`.
2. **Add file → Upload files**, перетащить изменившиеся файлы из `site/`.
3. Commit directly to the `main` branch → **Commit changes**.

Загружаются только страницы и `fingerprints.txt`. **`README.md` (этот файл) не загружается** —
он внутренний, в публичном репозитории ему делать нечего; если он там остался от прежних
публикаций, его можно удалить через тот же веб-интерфейс.

Имена файлов в корне репозитория менять нельзя: адреса страниц зашиты в приложении и в обеих
консолях магазинов.

Побочная польза ручной загрузки для `fingerprints.txt`: дату коммита в веб-интерфейсе ставит
сам GitHub, её нельзя проставить задним числом со своей машины — для записи, смысл которой в
датировке, это строго лучше пуша с локальной машины.

В настройках репозитория `mushrooms-map`: Settings → Pages → Deploy from a branch → `main`,
папка `/ (root)`. После этого доступны:

    https://leshy-mapper.github.io/mushrooms-map/privacy.html
    https://leshy-mapper.github.io/mushrooms-map/support.html
    https://leshy-mapper.github.io/mushrooms-map/fingerprints.txt

**Файл в репозитории обязан совпадать с опубликованным** (см. выше) — при ручной загрузке это
не обеспечивается само, поэтому после публикации стоит сверить:

```bash
curl -s https://leshy-mapper.github.io/mushrooms-map/privacy.html | shasum -a 256
shasum -a 256 site/privacy.html
```

Первый адрес зашит в приложении — `PRIVACY_POLICY_URL`
(`shared/src/commonMain/kotlin/leshy/mushrooms/map/ui/components/PrivacyPolicyLink.kt`),
единственное место, где он встречается; изменится хостинг — правится там.

Тот же URL идёт в Play Console (App content → Privacy policy) и в App Store Connect
(App Privacy → Privacy Policy URL); второй — в App Store Connect как Support URL. Обоим магазинам нужна страница, открывающаяся **без
авторизации и без редиректа на форму согласия** — GitHub Pages это условие выполняет; репозиторий
при этом должен быть публичным (для приватного Pages требует платный тариф).

## `fingerprints.txt` — отпечатки корпуса данных

Публикуется ради **даты**, а не ради содержания: каждая строка — SHA-256 снимка данных
каталога (состав и порядок подборок, выбор названий из синонимов, цвета плиток, хеши
картинок) на указанный день. Сам снимок остаётся в приватном репозитории
(`docs/release/fingerprints/`), публичной становится только его хеш — он ничего не
раскрывает, но привязан к точному содержанию. Смысл и порядок работы —
`docs/release/data-fingerprint.md`.

Обновляется не по релизам, а по заметному приросту данных: новый снимок
(`python3 tools/fingerprint.py`), новая строка сюда, та же ручная загрузка файла.

Там же — заявление о правах на приложение и его данные (английским: файл технический,
читают его в жалобе в стор, а русская версия того же заявления есть в подвалах обеих
страниц). Оно ничего не создаёт
(права возникают без уведомлений), но лишает копировальщика линии «мы думали, это свободные
данные» и даёт форме жалобы в стор то, на что сослаться.

## Что в тексте привязано к коду

Политика утверждает конкретные вещи о поведении приложения. Если меняется поведение — правится и
она; на 2026-09-07 сверено:

- название приложения — `StringKey.AppName`, в каждой языковой версии своё: «Грибная карта от
  Лешего», «Mushroom Map from Leshy», «Carte des champignons de Leshy», «Mapa de setas de Leshy»;
- когда читается геопозиция — `RecordViewModel` (экран «Запись» открыт **или** идёт запись, больше нигде);
- единственный сетевой адрес — `OPEN_FREE_MAP_STYLE_URL` (`ui/map/MapStyle.kt`) и тайлы оттуда же;
- отсутствие аналитики/крашлитики — по списку зависимостей `composeResources/files/aboutlibraries.json`;
- удаление прогулки уносит фотографии и миниатюру — `DeleteWalkUseCase`;
- разрешения — `androidApp/src/main/AndroidManifest.xml` и `iosApp/iosApp/Info.plist`;
- системный бэкап может копировать данные в облако пользователя — `android:allowBackup="true"`.
