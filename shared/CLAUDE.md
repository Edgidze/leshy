# Конвенции модуля shared

## Идентификаторы

- `namespace` = `leshy.mushrooms.map.shared`

Суффикс `.shared` существует **только в namespace**. Kotlin-пакеты внутри модуля идут
без него: `leshy.mushrooms.map.*`, а не `leshy.mushrooms.map.shared.*`. Namespace задаёт
лишь пакет генерируемого класса `R` и обязан быть уникален в пределах проекта.

## Room — схемы и миграции

- класс базы: `leshy.mushrooms.map.data.local.LeshyDatabase`
- каталог экспорта схем назван по полному имени этого класса. **При переименовании
  пакета или класса БД каталог нужно переименовать вручную** — иначе Room начнёт
  историю заново, без единой ошибки сборки
- каталог схем отслеживается git и должен оставаться в репозитории
- `.json` файлы схем **не редактировать руками** — они генерируются компилятором, ручная
  правка создаёт схему, которой никогда не существовало

### Версия 12 — базовая линия

Версия 12 будет первой опубликованной. Баз версий 1–11 вне машины разработчика
не существует и не появится, поэтому новые миграции обязаны уметь стартовать с 12,
а не с 1.

Схемы более ранних версий сохраняются для целостности истории и для цепочечного теста,
но практического значения для пользователей не имеют.

### fallbackToDestructiveMigration

Отсутствует в проекте намеренно. Не добавлять ни в каком виде, включая debug-сборки.

В релизе он не бросает исключение при ошибке миграции, а молча стирает базу — то есть
все находки пользователя, без единого сообщения. Отсутствие означает, что расхождение
схем проявится честным крашем на этапе разработки.

## Тесты миграций

Инструментальные тесты живут в source set `androidDeviceTest`, каталог схем подключён
к ним как assets.

Есть три теста:
- цепочечный v1→v12 через `runMigrationsAndValidate`
- сохранность данных для `MIGRATION_7_8`
- сохранность данных для `MIGRATION_9_10`

При добавлении новой версии БД:
1. поднять `version` в `@Database` и написать миграцию
2. собрать проект, убедиться что сгенерировался новый `.json`, закоммитить его
3. продлить цепочечный тест до новой версии
4. если миграция пересоздаёт таблицы, удаляет колонки или меняет типы — добавить
   отдельный тест на сохранность данных. `runMigrationsAndValidate` сверяет только
   схему и потерю строк не поймает

## Экспорт и бэкап

Версия формата экспорта дневника отделена от версии БД и не должна с ней связываться:
файлы экспорта переживают переустановку приложения, база — нет.
