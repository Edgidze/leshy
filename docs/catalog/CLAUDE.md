# docs/catalog/ — генератор каталога

`leshy_core_app.json` (источник) + `name_overrides.json` (ручной слой) →
`tools/build_catalog.py` → `shared/.../composeResources/files/catalog/` +
`shared/.../composeResources/drawable/`. Полное описание правил — план
`.claude/plans/countries-and-languages.md`, разделы 3 и «Фаза 0».

Запускать из корня репозитория: `python3 tools/build_catalog.py`.
Идемпотентен — переписывает все выходные файлы с нуля при каждом запуске,
безопасно перезапускать после правки источника или `name_overrides.json`.

## Правки поверх источника, зашитые в скрипт (не JSON-конфиг)

- Состав `RU`-подборки в `countries.json` отличается от присланного
  `country_presets.RU`: добавлены `GC0094`, `GC0007`, `GC0048`, `GC0031`,
  `GC0011`, убран `GC0165` — константы `RU_PRESET_ADD`/`RU_PRESET_REMOVE`.
  Причина и история решения — план, раздел 3.3.
- 6 групповых иллюстраций старого 30-категорийного каталога
  (`agaricus_species.webp` и т.д.) удаляются из `drawable/` как осиротевшие —
  `ORPHANED_GROUP_IMAGES`. `leshy_logo.webp`/`unknown_mushroom.webp` не из
  каталога, скрипт их не трогает; `suillus_luteus.webp` остаётся (`GC0023`
  есть в каталоге, просто не входит в `RU`).

**Отклонения от контрольных чисел плана:**

- Плановое число «372 различимых цвета на 408 категорий» — фактически
  **366**. Причина: раздел 3.5 не уточняет, взвешивать ли усреднение S/V
  победившего бина по насыщенности пикселя или брать простое среднее;
  реализован **простой (невзвешенный) среднее** — буквальное чтение
  «средние по пикселям». Проверено и взвешенным вариантом — даёт 375, то
  есть плановое число 372 лежит ровно между двумя разумными прочтениями
  формулировки. Расхождение — 1.6% от 408, не искажает цель приёма (избежать
  схлопывания в 7–8 цветов, как было у чистого hue-алгоритма); не считаю
  нужным подгонять реализацию под конкретное число вместо разумной формулы.
- «В среднем 48,4 различимых цвета на страну» — фактически **48,5**,
  совпадает в пределах округления.
- «У RU — 50 разных цветов на 50 видов» из плана относится к **исходному**
  50-позиционному `RU` (до правки 3.3, которая делается только для
  `countries.json`, а не для замера алгоритма). После правки 3.3 у RU 54
  позиции — фактически **54 разных цвета на 54 вида, ни одного повтора**
  (лучше, чем было бы при повторной проверке до правки).
- Остальное — без отклонений: 410 accessor-ов (408 + logo + unknown), нужные
  6 groupped-webp удалены, `suillus_luteus.webp`/`leshy_logo.webp`/
  `unknown_mushroom.webp` не тронуты, обмен именами опят (`GC0011`↔`GC0165`)
  в `names/ru.json` подтверждён, `amanita_vaginata` резолвится в «Поплавок
  серый» как и предсказывал план (3.4).

`app_assets_256/` удалён после подтверждения владельца проекта (данные из

## Фаза 3 (2026-08-25) — `countries/<lang>.json`

`tools/build_catalog.py` расширен новой секцией: `countries/en.json` и
`countries/ru.json` (`{countryCode: name}`, 33 страны каждый). Английский —
из `country_presets[cc]["country"]` источника как есть (включая `"Türkiye"`
для `TR` — это то значение, что реально лежит в `leshy_core_app.json`, не
подгонялось). Русский — источник его не содержит вообще (раздел 1 плана),
поэтому `RU_COUNTRY_NAMES` — рукописная таблица прямо в скрипте (33 строки,
рядом с `RU_PRESET_ADD`/`RU_PRESET_REMOVE`), тот же принцип «ручной слой
поверх генератора», что и `name_overrides.json`, но не вынесена в отдельный
JSON — 33×2 строки не оправдывают отдельный файл.

**Скрипт целиком после Фазы 0 больше не прогоняется end-to-end** —
`app_assets_256/` удалён (см. выше), а секция `catalog.json` требует его для
`dominant_color_hex`. Новая секция `countries/<lang>.json` от изображений не
зависит, но чтобы не задевать остальной (уже нерабочий без картинок) путь,
она была прогнана отдельно — импортом констант скрипта
(`RU_COUNTRY_NAMES`, `SOURCE_JSON`, `FILES_CATALOG_DIR`) в разовом снипете,
воспроизводящем ровно тот код, что лежит в `build_catalog.py`. Если
`app_assets_256/` когда-нибудь вернётся (например, для будущей
перегенерации каталога), `python3 tools/build_catalog.py` снова станет
прогоняемым целиком, включая эту секцию — специально ничего не разошлось.

Проверено скриптом по JSON напрямую: коды в `countries/en.json` и
`countries/ru.json` совпадают с кодами `countries.json` (33 = 33 = 33), обе
таблицы полные (`assert set(en) == set(ru) == codes`).
