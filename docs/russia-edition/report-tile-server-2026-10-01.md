## 3. Порядок работ брифа: подробно по шагам

### Шаг 0. Домен

### Шаг 1. Исходные данные
- ✅ `russia-latest.osm.pbf`, на сервере Geofabrik это `russia-260924.osm.pbf`: 4 165 390 325 байт,
  MD5 `8fd2d29d61690d5b9e460c05ebd9b195` совпал.
- Доработка относительно брифа: `build-tiles.sh` сначала узнаёт **датированное** имя файла через
  редирект Geofabrik, скачивает с докачкой (`curl -C - --retry 20`) именно его и рядом его MD5.
  Так докачка не склеит куски разных ежедневных версий, а MD5 не разойдётся с файлом
  после ночной пересборки Geofabrik.

### Шаг 2. Сборка тайлов
- ✅ Planetiler 0.10.2, Java 23.0.2, `-Xmx16g`. Машина: Intel i5-12600KF, 32 ГБ RAM, NVMe, Windows + Git Bash.
- **Отклонение от брифа: два прохода и склейка.** Planetiler обрезает все источники, включая
  Natural Earth и океан, по bbox экстракта (у России это широты ~41–82°). Одним проходом при отдалении
  получилось бы пустое полотно. Поэтому:
  1. Россия, bbox экстракта, z0–14 → `russia-z14.pmtiles` (7 646 484 881 байт), 27 мин 37 с;
  2. мир, `--bounds=world --maxzoom=6` (Natural Earth + водные полигоны + тот же российский экстракт)
     → `world-z6.pmtiles` (11,7 МБ), 3 мин 43 с;
  3. `scripts/merge_pmtiles.py` берёт z0–6 из мирового архива и z7–14 из российского.
     Склейка идёт на уровне записей каталога, тайлы не перепаковываются; ~1 мин.
- Брифовый `--area=russia` заменён на `--osm-path=russia-latest.osm.pbf --download`: экстракт качается и сверяется отдельно.

### Шаг 3. Проверка архива до заливки

## 6. Отклонения от брифа и самостоятельные решения (на согласование)

1. **Добавлен адрес рельефа** `/natural_earth/ne2sr/{z}/{x}/{y}.png`. Без него Liberty ходит к OpenFreeMap.
   Альтернатива — удалить источник `ne2_shaded` и его слой из стиля. Это нарушает «менять только URL»,
   но убирает 312 МБ статики и лишний адрес. **Нужно решение.**
2. **Сборка в два прохода и склейка** вместо одного прохода из брифа (причина — в шаге 2).
   В репозитории свой склейщик `merge_pmtiles.py` (≈100 строк на библиотеке `pmtiles`).
   Заголовок итогового архива (bounds/center) взят от российского прохода, `vector_layers` объединены.
3. **UA-фильтр только на `/tiles`.** Стиль, шрифты, спрайты и рельеф отдаются любому UA: приложение может
   грузить стиль своим HTTP-клиентом, а смысл фильтра — тайлы. В брифе путь не уточнён («всё прочее — 403»).
   **Подтвердить**, или распространить фильтр на все пути `tiles.`.
4. **Значения лимитов** подобраны с запасом на CGNAT мобильных операторов и офлайн-паки: тайлы 60 r/s + burst 600,
   64 соединения на IP. На живом приложении не проверены.
5. **Отсутствующий тайл → 204** (поведение `pmtiles serve`), а не 404. Бриф допускает оба варианта.
6. **Error-лог nginx для запросов → `/dev/null`.** Бриф требует только выключить access-лог,
   но в error-логе тоже оказывается IP клиента (например, в сообщениях `limit_req`).
   Минус: диагностировать проблемы на сервере будет труднее.
7. **Отдача через `pmtiles serve`**, а не Martin. Бриф допускает оба.
8. **Кэш-заголовки** (раздел 3, шаг 5): после обновления данных клиенты могут видеть старые тайлы до 7 дней.

## 7. Известные ограничения, риски, несоответствия

1. **Нет подписей соседних стран** («Казахстан», «Китай», «Финляндия» и т. д.): их узлы `place` лежат
   вне российского экстракта, а мировой проход берёт тот же экстракт. «Россия» и подписи регионов
   на месте. Бриф («подписи стран остаются») это формально не нарушает, но визуально на низких зумах
   соседи безымянны. Возможное исправление: во втором проходе подмешать небольшой экстракт с `place=country`
   по миру, например отфильтрованный planet или экстракты соседей. **Не делалось. Нужно решение.**
2. **Политика конфиденциальности расходится с реализацией.** В черновике `site/privacy.html` написано:
   «Собирается только обезличенная суммарная статистика нагрузки (например, число запросов в секунду)».
   Никаких метрик не реализовано, даже `stub_status`. Нужно либо убрать фразу, либо завести агрегатные метрики.
   Кроме того, это вообще черновик: окончательный текст должен прийти из трека приложения.
3. **Логи с IP, которые не относятся к пользователям приложения:** sshd (`auth.log`/journald) пишет IP
   тех, кто подключается по SSH, включая сканеры. С формулировкой «адреса нигде не записываются»
   формально конфликтует только если толковать её широко. Возможно, стоит уточнить формулировку
   («адреса пользователей приложения»).
4. **UA живого приложения не проверен.** Если MapLibre Native в приложении (Android/iOS) не шлёт подстроку
   `MapLibre` в `User-Agent`, карта получит 403 на все тайлы. **Это главный риск запуска.** Проверить до сдачи.
5. **nginx-конфиг ни разу не проходил `nginx -t`.** Синтаксис `listen 443 ssl http2` в nginx ≥ 1.25.1
   устарел (только предупреждение). В Ubuntu 24.04 стоит 1.24, в 22.04 — 1.18, так что работает.
6. **`server-setup.sh` выключает access-лог правкой `sed`** строки `access_log /var/log/nginx/access.log;`
   в стандартном `nginx.conf` Ubuntu. Если строка там другая, правка молча не сработает. Защищает от этого
   то, что `access_log off` стоит и в конфиге сайта на уровне http. Но приёмочную проверку
   «файла нет после серии запросов» делать обязательно.
7. **Мониторинга и алертов нет** (uptime, место на диске, срок сертификата). Бриф его не требует.
   Агрегатные метрики разрешены, но не сделаны.
8. **Обновление данных ручное**, по сценарию из README, без cron. Это соответствует брифу («раз в несколько месяцев»).
9. **Скрипты рассчитаны на Linux x86_64 и Ubuntu 22.04/24.04.** Сборка проверена на Windows + Git Bash,
   на Linux-машине сборки `build-tiles.sh` не запускался, хотя должен работать.
10. Если GitHub с VPS недоступен, `go-pmtiles` для сервера передаётся заранее
    (`C:\tiles-build\go-pmtiles_1.31.2_Linux_x86_64.tar.gz` → `/tmp/go-pmtiles.tgz`).

## 8. Что осталось сделать (по порядку)

### Блокеры запуска
1. ~~Запушить репозиторий~~ — сделано 2026-10-01.
2. **Выбрать и заказать VPS у sweb.** С учётом фактического размера архива: ≥ 2 ГБ RAM (лучше 4 ГБ под
   файловый кэш), ≥ 40–60 ГБ NVMe, Ubuntu 24.04, root по SSH, дата-центр в РФ. Результат исследования
   по промпту в репозиторий не записан.
3. **DNS:** A-записи `gribnye-progulki.ru` и `tiles.gribnye-progulki.ru` → IP VPS. Если у VPS есть IPv6 — AAAA,
   nginx уже слушает `[::]`.
4. **Окончательный текст политики конфиденциальности** из трека приложения → `site/privacy.html`.
   Заодно устранить расхождение про «статистику» (раздел 7, п. 2).
5. **Развёртывание:**
   ```bash
   scripts/upload.sh root@VPS C:/tiles-build
   scp C:/tiles-build/go-pmtiles_1.31.2_Linux_x86_64.tar.gz root@VPS:/tmp/go-pmtiles.tgz
   ssh root@VPS 'bash /root/rus-map-tiles-server/scripts/server-setup.sh'
   ssh root@VPS 'bash /root/rus-map-tiles-server/scripts/switch-release.sh /srv/tiles/incoming/russia-20260926.pmtiles'
   ```
   Дата в имени файла берётся из mtime экстракта. Заливать ~7,7 ГБ.
6. **Приёмка с российского подключения**: весь раздел 5, включая мобильный интернет, UA живого приложения
   и отсутствие 429 при панорамировании.
7. **Заполнить `ACCEPTANCE.md`** фактическими результатами, закоммитить.
8. **Отдать в трек приложения:** базовый URL `https://tiles.gribnye-progulki.ru`, подтверждение приёмки,
   имя спрайта `liberty`, факт существования адреса рельефа.

### Решения, которые ждут владельца (см. разделы 6–7)
- оставить зеркало рельефа или убрать `ne2_shaded` из стиля;
- UA-фильтр только на `/tiles` или на всё;
- подмешивать ли подписи соседних стран;
- агрегатные метрики: делать или убрать упоминание из политики;
- e-mail для Let's Encrypt.

### Желательно, но не обязательно
- `nginx -t` в контейнере/WSL до выезда на сервер;
- простейший внешний uptime-мониторинг без IP пользователей;
- агрегатный `stub_status` на localhost, если метрики остаются в политике.
