# Релизная подготовка iOS — инструкция для агента

Путь в репозитории: `docs/release/ios-app-store-setup.md`
Парный документ по Android — `docs/release/android-release-setup.md`.

Цель — довести проект до состояния, когда подписанный архив принимается App Store Connect,
раздаётся тестировщикам через TestFlight и проходит ревью в App Store.

Задачи выполнять **строго по порядку**, каждая — отдельная сессия агента (`/clear` между
задачами). Этот файл в контекст автоматически не подтягивается: ссылайтесь на него явно,
например «выполни задачу 3 из `docs/release/ios-app-store-setup.md`».

У каждой задачи указан исполнитель: **владелец** (действия в консолях Apple и в Xcode, агент
туда не ходит) или **агент** (правки в репозитории).

## Где остановились (обновлять при каждом обрыве сессии)

**14.09.2026.** Загружен билд `1.0 (2)`, App Apple ID `6811357888`. Билд `1.0 (1)` получил
`ITMS-90683` и остался в консоли негодным для ревью; во втором замечание закрыто.

Что выяснилось по дороге и чего не было в плане:

- **В Xcode был залогинен не тот Apple ID.** Подпись шла от бесплатной команды
  `78XLSLLP9C` (приметы: profile с `TimeToLive = 7`, у платной — 365). Платный аккаунт
  добавлен, `DEVELOPMENT_TEAM` в `project.pbxproj` теперь `6UHK58SAU6`; там же, в платной
  команде, зарегистрирован `leshy.mushrooms.map` («Mushroom map from Leshy»), то есть подпись
  и запись приложения в одной команде. Старый сертификат и семидневный профиль остались в
  связке, ни на что не влияют.
- **Смена команды требует зарегистрированного устройства.** Профиль `iOS App Development`
  не выдаётся, пока в команде нет ни одного устройства, — отсюда «Your team has no devices…»
  и «Communication with Apple failed». Регистрация асинхронная (`status: PROCESSING`), первый
  `Try Again` ещё падает, второй проходит. На архив для App Store это не влияет вовсе:
  distribution-профиль устройств не требует.
- **`Upload Symbols Failed` на загрузке — ожидаемо и не блокирует.** У `MapLibre.framework`
  нет своего `.dSYM`: она приходит собранной. Символы приложения ушли полностью — Kotlin
  слинкован статически, всё лежит в `leshy.app.dSYM`. Следствие для задачи 10: кадры внутри
  MapLibre в отчётах ASC останутся несимволизированными, как и в расследовании фонового
  зависания.
- **`ITMS-90683` потребовал `NSLocationAlwaysAndWhenInUseUsageDescription`** — из-за
  `requestAlwaysAuthorization` внутри `MapLibre.framework`: наш код просит только
  `requestWhenInUseAuthorization`. Purpose-строку может потребовать чужая зависимость, разбор
  и способ проверки — в `iosApp/CLAUDE.md`. Письмо приходит через несколько минут после
  загрузки и **не мешает обработке билда**, но закрывает ему дорогу на ревью, в том числе
  облегчённое для внешнего TestFlight.
- **Экрана с опциями «Upload your app's symbols» / «Manage Version and Build Number» в
  Xcode 26 на обычном пути нет** — он за `Distribute App → Custom`. Значения по умолчанию
  подходят; на первой загрузке номер билда всё равно не с чем конфликтовать.

Открытые хвосты: статус трейдера (задача 1) — подтвердить, что отвечен; девять
`values-*/strings.xml` на Android — косметика ярлыка лаунчера, уедет с ближайшей сборкой в

## Решения владельца — агент их не пересматривает

| Решение | Значение | Почему так |
|---|---|---|
| Обфускация релиза | **не делается** | на iOS нет аналога R8: Kotlin/Native — машинный код, Apple обфускации не требует. Единственное, что нужно от релизной сборки, — сохранённые `.dSYM` (уже автоматизировано в `iosApp/Scripts/archive-symbols.sh`) |
| iPad | **сейчас `TARGETED_DEVICE_FAMILY = "1"`** | расширение `"1"` → `"1,2"` после релиза — обычное обновление без потери отзывов и установок; обратное направление лишает уже установивших iPad-пользователей обновлений. На iPad приложение работает в режиме совместимости |
| Зависание MapLibre в фоне | **не чинится до релиза** | класс инцидента ограничен эффективно-двухъядерными iPhone (A9/A10 = ровно те, что застряли на iOS 15). Сначала собирается статистика установок по моделям, потом принимается решение. План фикса готов и лежит: `.claude/plans/ios-maplibre-pause-observer.md` |
| `IPHONEOS_DEPLOYMENT_TARGET` | **15.0, не поднимать** | подъём до 16.0 отсёк бы ровно группу риска, но вместе с ней — единственное устройство, на котором баг воспроизводится (iPhone SE 2016 владельца) |
| Bundle ID | `leshy.mushrooms.map` | привязывается к записи App Store навсегда |
| `MARKETING_VERSION` | совпадает с `leshy.versionName` Android | одна версия приложения в обоих магазинах |
| Политика конфиденциальности | тот же URL, что в Play | требование обоих магазинов — открываться без авторизации |
| Тексты и картинки листинга | переиспользуются из `docs/store/play/` | дописываются только поля, которых в Play нет |
| Локали листинга | **en-US и ru-RU**, primary language записи — **English (U.S.)** | как в Play. Primary — фолбэк для всех стран без своей локализации, меняется потом тяжело; остальные языки добавляются позже |
| Доступность | все регионы | ЕС открывается ответом про статус трейдера (задача 1); материковый Китай требует номер ICP-регистрации — проверить на шаге доступности и при отсутствии снять галочку |

**Что агенту запрещено:** поднимать deployment target, включать iPad, начинать фикс MapLibre,
править `project.pbxproj` без последующей проверки по разделу «Имя продукта живёт только в
`Config.xcconfig`» (`iosApp/CLAUDE.md`) — у этого файла в проекте уже была история с
обнулением `PRODUCT_NAME`.

## Задача 1. App Store Connect: соглашения, статус трейдера, запись приложения

**Исполнитель: владелец.** Запускается первой — часть шагов ждёт ответа Apple.

1. **Agreements, Tax and Banking** — принять соглашение для бесплатных приложений. Без него
   приложение не может быть распространено, и это выясняется в самом конце.
2. **Статус трейдера для ЕС.** Требование европейского Digital Services Act: маркетплейс
   обязан показывать контактные данные продавца-профессионала. Apple сделала из этого
   обязательную декларацию — **ответить нужно в любом случае**, иначе приложение просто не
   показывается в витринах ЕС, а для приложения с подборками по пятнадцати европейским странам
   это перечёркивает половину смысла.

   Где: App Store Connect → **Business** (раздел с соглашениями и налоговыми данными) → пункт
   про **trader status**; точное название пункта Apple периодически меняет, ориентир — слово
   «trader». Отвечает владелец учётной записи.

   Что отвечать. «Трейдер» в терминах ЕС — тот, кто действует в целях своей торговой,
   предпринимательской или профессиональной деятельности. Бесплатное приложение физлица без
   рекламы, без встроенных покупок и без донатов под это, как правило, не подпадает.

   | Ответ | Что за этим следует |
   |---|---|
   | **не трейдер** | адрес и телефон публично на странице приложения не показываются, верификация не нужна |
   | трейдер | Apple проверяет адрес, телефон и email, после чего публикует их в карточке приложения; проверка занимает время |

   **Формулировку в консоли прочитать самостоятельно и ответить по факту** — это юридическое
   заявление от своего имени, агент за вас его не интерпретирует. Если в приложении когда-нибудь
   появится любая монетизация, включая донаты, статус придётся сменить на «трейдер».
   **Решение 24.09.2026: ответ «не продавец», менять не нужно.** Разбор понадобился, потому
   что русский диалог в консоли формулирует вариант как «Я не продавец согласно DSA **и не
   планирую распространять контент на территории ЕС**», и это читается как отказ от витрин ЕС —
   а у приложения 26 из 55 страновых подборок приходятся на страны ЕС. Проверено по справке
   Apple (App Store Connect Help, «Manage European Union Digital Services Act trader
   requirements»), и она говорит другое:

   - **последствие ответа «не продавец» — уведомление, а не исключение:** «If you're not a
     trader, consumers in the EU will be informed that consumer rights stemming from applicable
     consumer protection laws won't apply to contracts between you and them»;
   - **витрины ЕС закрывает ОТСУТСТВИЕ декларации, а не сам ответ:** «Even if you don't
     distribute apps in the EU, you'll still need to declare a trader status»;
   - **в английской справке варианты названы просто** «This is a trader account.» / «This is
     not a trader account.» — оговорки про намерение распространять в ЕС там нет вовсе (искал
     по всей странице); русская формулировка расходится со справкой;
   - **случай проекта описан в справке буквально:** «if you're a hobbyist and you developed
     your app with no intention of commercializing it, you may not be considered a trader».

   Статус можно переопределять отдельно для каждого приложения («You'll then have the option
   to turn off or specify your trader status for each specific app»), то есть решение не
   глобальное и обратимое.

   **Когда вернуться к вопросу:** появление любой монетизации, включая донаты. И ещё —
   формулировку диалога стоит однажды перечитать на английском (селектор языка внизу страницы
   ASC): если оговорка про ЕС окажется и там, вывод придётся пересматривать.

3. Зарегистрировать **Bundle ID** `leshy.mushrooms.map` (или дать Xcode создать его при первом
   архиве) и завести **запись приложения**:
   - **Name** — «Mushroom Map from Leshy» (23 символа, из `docs/store/appstore/listings.json`);
   - **Primary language — English (U.S.)**: это фолбэк для всех стран, где своей локализации нет,
     и меняется он потом тяжело;
   - категория и SKU — на усмотрение владельца (SKU виден только в консоли).
4. Заполнить **App Review Contact** — имя, телефон, email для связи ревьюера (не публичное
   поле, страницей поддержки не заменяется).

**Критерий готовности:** запись приложения существует, в ней нет предупреждений про соглашения
и статус трейдера, билды к ней можно загружать.

## Задача 2. Правки проекта под distribution

**Исполнитель: агент. Модель: Sonnet.** Механическая правка конфигов.

**Сделано 12.09.2026** — правки внесены, проверки пройдены, контрольная сборка под симулятор
показывает в бандле 42 локализации и `ITSAppUsesNonExemptEncryption = false`. Ручных действий
в Xcode не потребовалось (см. про синхронизированные папки в пункте 4).

1. `iosApp/iosApp/Info.plist` — добавить:

```xml
<key>ITSAppUsesNonExemptEncryption</key>
<false/>
```

   Приложение ходит только по HTTPS к OpenFreeMap, это штатное исключение экспортного
   контроля. Без ключа билд в TestFlight повисает со статусом Missing Compliance и не
   раздаётся тестировщикам.

2. `iosApp/iosApp.xcodeproj/project.pbxproj`:
   - в **обеих** конфигурациях таргета `TARGETED_DEVICE_FAMILY = "1,2"` → `"1"`;
   - `CODE_SIGN_IDENTITY` **не трогать**. Проверено 12.09.2026: при `CODE_SIGN_STYLE =
     Automatic` попытка прописать `"Apple Distribution"` в Release ломает архив на старте —
     «iosApp has conflicting provisioning settings… automatically signed for development, but a
     conflicting code signing identity Apple Distribution has been manually specified».
     Автоматическая подпись подставляет distribution-сертификат сама, на этапе Distribute App;
     `"Apple Development"` в build settings — это её штатное значение, а не недосмотр.

3. Проверить `TEAM_ID=` в `iosApp/Configuration/Config.xcconfig`: переменная пустая. Если
   `grep -rn "TEAM_ID" iosApp/` не находит ни одного её использования — **не трогать**,
   подпись берёт `DEVELOPMENT_TEAM` из `project.pbxproj`.

4. **Дозаполнить локализации бандла.** В приложении 42 языка интерфейса (`AppLanguage.kt`),
   а в `iosApp/iosApp/` только 33 папки `.lproj`; нет девяти — `bs`, `da`, `el`, `is`, `mk`,
   `nb`, `nl`, `pt`, `sq` (партия `europe-15`). Завести каждой свой
   `<код>.lproj/InfoPlist.strings` с `CFBundleDisplayName` — **коротким ярлыком** в стиле
   существующих (`"Грибная карта"`, `"Pilzkarte"`), а не полным `StringKey.AppName`
   («Mushroom Map from Leshy»); названия на этих языках уже есть в
   `shared/…/i18n/strings/Strings<Xx>.kt`.

   **В таргет их добавлять не надо.** Проект собран на синхронизированных папках Xcode 16
   (`PBXFileSystemSynchronizedRootGroup`, `objectVersion = 77`): каталог `iosApp/iosApp`
   принадлежит таргету целиком, и любой новый файл в нём попадает в сборку сам. Список
   `knownRegions` в проекте уже содержит все 42 языка.

   Зачем это в релизной задаче: список языков на странице приложения в App Store выводится
   из локализаций **бандла**, а не из локализаций листинга, — без этих девяти файлов языки не
   попадут в карточку, а ярлык на домашнем экране останется базовым «Mushroom Map».

5. Записать в `iosApp/CLAUDE.md` короткий раздел про номер билда: `CURRENT_PROJECT_VERSION`
   — аналог `versionCode`, обязан расти на каждую загрузку в пределах одного
   `MARKETING_VERSION`, иначе App Store Connect отвечает «The bundle version must be higher
   than the previously uploaded version».

**Критерий приёмки:**

```bash
./gradlew :shared:compileKotlinIosArm64
grep -n "productReference\|path = .*\.app" iosApp/iosApp.xcodeproj/project.pbxproj
```

Первое проходит; во втором **нигде нет** `path = .app` (обнулившееся `PRODUCT_NAME` — известная
ловушка проекта, см. `iosApp/CLAUDE.md`). `git diff` содержит ровно три смысловые правки и
ничего больше.

## Задача 3. Privacy manifest

**Исполнитель: агент пишет файл, владелец добавляет его в таргет.**
**Модель: Sonnet.**

**Сделано 12.09.2026** (`iosApp/iosApp/PrivacyInfo.xcprivacy`, `plutil -lint` проходит).
Контрольная сборка подтверждает: файл лежит в корне `leshy.app`. Добавлять его в таргет руками
не понадобилось.

Privacy manifest — машиночитаемый файл внутри бандла, не имеющий отношения к анкете App
Privacy в консоли. Без него после загрузки приходит письмо `ITMS-91053: Missing API
declaration`, блокирующее публикацию.

1. Агент создаёт `iosApp/iosApp/PrivacyInfo.xcprivacy`:
   - `NSPrivacyTracking` = `false`, `NSPrivacyTrackingDomains` — пустой массив;
   - `NSPrivacyCollectedDataTypes` — пустой массив (приложение не собирает ничего: нет
     аналитики и крашлитики, единственный сетевой адрес — тайлы OpenFreeMap, всё хранится
     на устройстве; фактура — `site/README.md`, раздел «Что в тексте привязано к коду»);
   - `NSPrivacyAccessedAPITypes` — категории, которые даёт не свой код, а библиотеки,
     влинкованные в `Shared.framework`:
     - `NSPrivacyAccessedAPICategoryFileTimestamp`, причина `C617.1` (файлы внутри
       контейнера приложения) — okio/DataStore/Room;

## Задача 10. После релиза: наблюдение и решение по MapLibre

**Исполнитель: владелец смотрит консоль, агент выполняет план фикса, когда решение принято.**

1. **App Store Connect → Analytics** даёт разбивку установок и сессий **по моделям
   устройств**, крэши и зависания — тоже по моделям. Это прямой ответ на вопрос «сколько
   пользователей в зоне риска»: интересуют iPhone 6s / 6s Plus / SE (2016) / 7 / 7 Plus —
   эффективно двухъядерные A9/A10, они же ровно те, кто застрял на iOS 15.
2. Признак того самого класса инцидентов: `EXC_CRASH (SIGKILL)`, `0x8BADF00D`, FRONTBOARD,
   стек главного потока с кадрами `MapLibre.framework` и `std::future<void>::get()`.
3. Когда решение принято — выполнять `.claude/plans/ios-maplibre-pause-observer.md` (снятие
   наблюдателя `pauseFileSource:`, около десяти строк в `PlatformModule.ios.kt`). Проверять
   **только на устройстве**: карта, активная запись, свернуть-развернуть 20 раз подряд. У
   правки есть своя цена — MapLibre продолжит работать с SQLite в фоне, следить за
   `disk I/O error` в логах долгих прогулок с заблокированным экраном.
4. Независимая от ядер ветка риска на тех же старых устройствах — **память**: измеренный пик
   591 МБ `lifetimeMax` при 2 ГБ на борту. В расследовании эта ветка не заведена; если в
   аналитике окажутся заметные потери сессий на старых моделях, начинать надо с неё, а не с
   фикса из пункта 3.
