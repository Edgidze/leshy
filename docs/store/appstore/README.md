# `docs/store/appstore` — страница приложения в App Store

Тексты и графика для листинга App Store. Парный каталог по Google Play — `../play`, оттуда
переиспользуются название, полное описание, демо-архивы и сырые кадры скриншотов.

## Что здесь

| Файл | Что это |
|---|---|
| `listings.json` | **Источник правды.** `{ "<locale>": { "title", "subtitle", "keywords", "promotional_text", "description" } }` |
| `render_listings.py` | Проверка лимитов + генерация `listing_<locale>.md` |
| `listing_<locale>.md` | По файлу на локаль, для ручной вставки в консоль — генерируется, руками не править |
| `review-notes.md` | Текст для App Review Information → Notes (по-английски) |
| `graphics/phone-<lang>/` | Скриншоты 1320×2868 — комплект 6.9" iPhone |

## Чем App Store отличается от Play — то, на чём легко споткнуться

- **Импорта метаданных из файла в веб-консоли нет.** У Play есть шаблон массового импорта
  переводов (под него сделан `../play/listings.csv`); здесь поля либо заполняются руками по
  локали, либо пушатся через App Store Connect API. Ради двух локалей API не заводим — отсюда
  `listing_<locale>.md` для копипасты и **никакого CSV**.
- **Локализации листинга — часть версии.** В Play страница живёт отдельно от выпусков, здесь
  добавление языка уезжает вместе со следующей отправкой версии и проходит ревью с ней. Свободно
  правится только Promotional Text.
- **Другие поля и лимиты:**

  | Поле | Лимит | Откуда |
  |---|---|---|
  | Name | 30 | из Play без изменений |
  | Subtitle | 30 | своё: короткое описание Play (70–72 символа) не влезает |
  | Keywords | 100, через запятую | своё, аналога в Play нет |
  | Promotional Text | 170 | своё, необязательное; единственное поле, которое можно менять без новой версии |
  | Description | 4000 | из Play без изменений |

  В keywords **не повторяются слова из названия** — оно индексируется само, повтор тратит символы.
- **Иконка 1024×1024 не загружается отдельно** — App Store берёт её из бандла
  (`iosApp/iosApp/Assets.xcassets/AppIcon.appiconset`, PNG без альфы). Баннера, как
  `feature-graphic` у Play, здесь нет вовсе.
- **Локали приложения ≠ локали листинга.** Список языков на странице App Store выводится из
  локализаций бандла (`iosApp/iosApp/<язык>.lproj`), а не из числа переведённых листингов: все 42
  языка интерфейса видны в карточке, даже когда сама страница на двух.

## Как обновить тексты

Правится `listings.json`, дальше:

```bash
python3 render_listings.py          # перегенерировать listing_<locale>.md и проверить лимиты
python3 render_listings.py --check  # только проверить
```

Скрипт отказывается писать файлы, если какое-то поле длиннее лимита. Лимит проверяется **для
каждой локали отдельно** — перевод, который вырос при переводе, самый обычный способ получить
отказ.

## Как пересобрать скриншоты

Пересъёмка на iOS **не нужна**: в кадрах срезаны статус-бар и жестовая полоса, рамки устройства
нет, интерфейс Compose Multiplatform на iOS тот же. Отличается только размер холста, и он задан
пресетом в общем скрипте:

```bash
python3 ../play/compose_shots.py en --preset appstore \
    --raw ../play/graphics/raw-en --out graphics/phone-en --font <путь>/NotoSans.ttf
python3 ../play/compose_shots.py ru --preset appstore \
    --raw ../play/graphics/raw-ru --out graphics/phone-ru --font <путь>/NotoSans.ttf
```

Исходный кадр 1080 px вписывается в 1100 px холста 1320 px — увеличение около 2%, деградации нет.

**Шрифт подписей в репозитории не лежит** (бинарь шрифта — не исходник проекта). Скрипт ищет его
по списку кандидатов (`fonts/NotoSans.ttf` в рабочем каталоге, `~/Library/Fonts/`, системный
Arial Bold), путь перебивается `--font` или `LESHY_CAPTION_FONT`. Комплект в репозитории собран
статическим **NotoSans-Bold** — исходный прогон для Play шёл на вариативном NotoSans с осями
`[100, 700]`, так что при побайтовом сравнении наборы не совпадут; визуально это тот же шрифт.

Комплект для iPad **не готовится**: `TARGETED_DEVICE_FAMILY = "1"`, приложение объявлено только
для iPhone (решение зафиксировано в `docs/release/ios-app-store-setup.md`).
