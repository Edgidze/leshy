# fishing/ — рыбацкий продукт «Клёв»

Второе приложение из этого репозитория: трекинг рыбалки (трек + улов поштучно +
погода выезда), архив выездов, карта улова, разбор «что работало». Модуль зависит
на `:shared` и **не меняет в нём ничего** — проверка механическая:

```bash
git diff --stat main...HEAD -- shared/ androidApp/ gradle.properties
```

Пусто — значит грибные приложения остались теми же. Общий разбор семейства —
`.claude/plans/product-family.md`, проработка интерфейсов и внешняя фактура по
запросам рыболовов — `.claude/plans/fishing-ux.md`.

## Решения, которые нельзя вывести из кода

- **Улов пишется в Room в момент касания плитки** — без веса, без диалога, без
  единого обязательного поля (`TripViewModel.quickCatch`). Это не упрощение
  формы, а ответ на факт: дневник, в котором запись занимает больше времени, чем
  вытащить рыбу, перестают вести через пару выездов. Всё остальное — вес,
  приманка, исход — дописывается позже тем же листом (`CatchSheet`), в том числе
  через недели, с экрана выезда. Поэтому **лист правки обязан уметь ВСЁ, что
  умеет лист новой записи**, включая смену вида: промах по соседней плитке — самая
  вероятная ошибка быстрой записи.
- **Способ ловли не выбирается за пользователя.** Спиннинг/поплавок/лодка/лёд —
  это настройка «мои способы» (`FishingSettingsRepository.observeMethods`), и
  экран старта предлагает только их. Решение владельца 2026-09-28: не угадывать
  целевую аудиторию. Пустое множество наружу не отдаётся никогда — иначе рыбалку
  нельзя начать вообще.
- **Разделы — боковое меню, не нижняя панель.** Их станет больше, чем влезает в
  bottom bar (экспорт/импорт, офлайн-карта, подборки видов по регионам). Механика
  перехода — грибная, `navigateToTopLevel` в `ui/navigation/FishDestination.kt`,
  вместе с её причиной: смешивать её с голым `navigate()` нельзя (у грибов это
  стоило нескольких настоящих багов, разбор — `ui/navigation/CLAUDE.md` в
  `:shared`). Пунктов-заглушек в меню не заводить: пункт, открывающий «пока
  ничего», хуже отсутствующего.
- **Тема — `FishingTheme`, обёртка вокруг `LeshyTheme`, а не своя с нуля.**
  Композаблы `:shared` (подписи-обводки на плитках, размеры диалогов, карта)
  читают `LeshyTheme.tokens`; поэтому каркас берётся у мировой грибной редакции, а
  цвета переопределяются вложенным `MaterialTheme`. Инверсные цвета
  (`inverseSurface`/`inversePrimary`) задавать обязательно — на них рисуется
  снэкбар, и без них он остаётся фиолетовым из базовой палитры Material.
- **Карта обслуживается так же, как у грибов.** `FishingApp` обязан звать
  `MapStyleCacheRepository.setLabelLanguage`/`setDarkTheme`/`ensureLoaded` — стиль
  общий, и без этих трёх строк карта в тёмной теме остаётся светлым пятном.
- **Формат иллюстраций видов — 2:1, горизонтальный** (`FISH_PLATE_ASPECT_RATIO`).
  Картинки рисует владелец; пока их нет, плитка показывает силуэт рыбы цветом вида
  (`FishSilhouette` — единственная нарисованная мной графика, разрешённая как
  заглушка). Подпись лежит ПОВЕРХ площадки: строкой под картинкой плитка
  становится тем выше, чем длиннее название, и лента рассыпается в гребёнку.
- **Локализация — пока только ru + en** (`FishStrings.kt`). Это исключение из
  правила проекта «новая строка сразу во все языки», выданное владельцем на время,
  пока тексты не устоялись; на грибное приложение оно не распространяется.
- **Карта рыбалки — своя (`ui/map/CatchMap.kt`), а не `AggregatedFindsMap` из
  `:shared`:** тот слой группирует отметки по иллюстрации и молча выбрасывает те, у
  которых её нет, — у рыб сейчас нет ни у одной. Там же обработана вырожденная
  рамка: вся рыба с одной точки уводила камеру на предельный зум тайлового сервера.
- **iOS-цели у модуля пока нет сознательно** — нужен отдельный шаг с правкой
  `iosApp.xcodeproj` и SPM-обвязкой MapLibre; поэтому весь код лежит в
  `commonMain`, чтобы добавление цели осталось правкой одного build-файла. Из
  этого следует: `ModalBottomSheet` и прочее, что здесь работает, на iOS ещё
  никто не проверял.
